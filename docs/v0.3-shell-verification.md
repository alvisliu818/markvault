# markvault v0.3 桌面壳点验清单

> 目的：补上 E2E 覆盖不到的部分——E2E 跑在 headless Edge（浏览器环境），**触不到 Tauri IPC、WebviewWindow、rfd 原生对话框与注册表**。
> 状态：2026-11-11 完成 17 项自动点验 + 4 缺陷修复；2026-11-12 剩余 7 项中的 6 项经 `frontend/e2e/shell_manual.mjs`（壳+CDP）与 `manual7.mjs`（web）自动化完毕——**仅剩 C1（rfd 原生模态）需人工**。

## 1. 启动方式（只用测试 vault）

```bash
cd E:/HOME/Code/markvault/app/src-tauri
MARKVAULT_WORKSPACE="E:/HOME/Code/markvault/testvault" \
MARKVAULT_KERNEL="E:/HOME/Code/markvault/target/debug/markvault-kernel.exe" \
WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9223 --remote-allow-origins=*" \
./target/debug/markvault-app.exe
```

- `MARKVAULT_WORKSPACE` 覆盖 `%APPDATA%/markvault/config.json`（本机当前无该文件），**不写用户配置、不碰主库**。
- `MARKVAULT_KERNEL` 指向最新构建的内核；不指定会用到 10:18 的旧 sidecar。
- 内核每次启动取随机端口，主窗口加载 `http://127.0.0.1:<port>`（remote origin）。CDP 用于自动化点验，正式使用可去掉 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`。
- 日志：`testvault/.markvault/logs/kernel.log`；CDP：`http://127.0.0.1:9223/json`。
- ⚠️ 常驻进程后台启动**不要接管道**（`| Select-Object -First N` 会在收满 N 行后断管道，stderr 后续写入会杀掉进程）。

## 3. 本轮发现并修复的 4 个真实缺陷

| # | 现象 | 根因 | 修法 | 验证 |
|---|---|---|---|---|
| 1 | 设置对话框打开后「取消/保存」按钮被挤出可视区，点击被遮罩拦截；壳设置/工作区/插件三块挤成一行 | `settings.ts` 壳设置区用 `insertAdjacentHTML("beforeend")` 插进了 `.actions`（flex 按钮行）内部；对话框也无高度上限 | 改成与另两块一致的 `"beforebegin"`；`.mv-dialog` 加 `max-height: calc(100vh - 80px); overflow-y: auto`，`.actions` sticky 置底 | 修复后 `.actions` 只剩 2 个按钮、对话框高 780 ≤ 视口 860、取消可点且正常关闭 |
| 2 | **点「新页签」后整个壳卡死**：窗口建出来（about:blank / chrome-error），但所有 Tauri IPC 无响应、页面 JS 后续定时器也不再执行 | 同步 `#[tauri::command]` 占用主线程时调用 `WebviewWindowBuilder::build()`，WebView2 控制器创建需要同一主线程泵消息 → 自锁 | `browser.rs` 的 5 个窗口命令改为 `async fn`，统一经 `on_main()`（`run_on_main_thread` + oneshot 回传）派发 | 带 CDP 与不带 CDP 均复现过；修复后 `browser_open` 正常返回、`ws_list` 仍通，B1-B9 全绿 |
| 3 | **关掉一个浏览器页签后所有 HTTP API 报 `Failed to fetch`**，工作区实例被清空 | `main.rs` 的 `on_window_event(Destroyed)` 没判断窗口 label，任意窗口销毁都 `kill_all()` 杀光内核实例 | 仅 `window.label() == "main"` 时才 `kill_all()` | 关页签后 `/api/system/health` POST 200、实例数不变 |
| 4 | 「切回初始工作区」会多启动一个内核实例（1→2→3），`ws_close` 后仍残留 2 个 | 启动实例用原始 env 路径 `E:/...` 注册，而 `ensure_instance`/`norm` 用 canonicalize 后的 `\\?\E:\...` 匹配，永远命中不了 | `main.rs` 启动实例同样 canonicalize 后注册 | 切换序列 1→2→2→1，C4/C4b/C5 全绿 |

> 另有一处方法论记录：第一次自动探针因设置对话框未关闭而连锁超时（30s/项），已改为「默认短超时 + 每项独立 try/catch + DOM 层直接触发」；`page.evaluate` 本身无超时，需用 `Promise.race` 包裹 IPC 调用，否则会永久挂起。
